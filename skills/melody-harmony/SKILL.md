# Melody Harmony — 和弦、情绪与编曲 Skill

## 目的

帮助 AI 在已有旋律上进行**可解释的和声推理和编曲规划**。不是静态“快乐/悲伤按钮”，情绪词只能是语境依赖的倾向。先处理调性、旋律、和声功能和声部进行，再用风格/速度/乐器调整气质。

## 加载知识（按任务选择，不必一次全读）

这些文件随 Melody Notation 项目打包，路径相对于**项目根目录**：

- `src/harmony/chords.md`：和弦构成、符号、常见情绪、用法、禁忌；当用户问“这个和弦”时首先读取。
- `src/harmony/progressions.md`：C 大调、A 小调以及借用/副属/Lo-fi/8-bit 进行；用户要歌曲/场景和弦时读取。
- `src/harmony/workflow.md`：按旋律配和弦、输出审查计划和检查表；编辑现有作品时必读。
- `src/harmony/sources.md`：来源与审美推断边界；解释和弦情绪时参照。
- `src/harmony/chords.json`：机器可读的和弦类型、音程及示例音；用于精确查音高。

若本 Skill 被单独复制到其他仓库，这些参考文件也在本 Skill 的 `references/` 目录中，可用相对路径加载，不依赖原仓库结构。

## 必须遵守的工作流

1. **弄清输入**：旋律、当前调号（包括中途转调）、节拍、BPM、目标情绪/风格/音色；不要在没有调号时默认用户一定要 C 大调。
2. **先检旋律**：强拍、长音、乐句终止、音域和旋律中明显的非和弦音；识谱不确定时先报告。
3. **两种方案**：提供基础功能和弦版与风格/色彩版，逐小节说明和弦名、罗马数字、重要旋律匹配和情绪/紧张度设计。
4. **正确拼写**：`Cmaj7=C–E–G–B`；`C7=C–E–G–B♭`；`Csus4` 通常不用 E；`Cadd9` 没有 B♭。小调强属 `V7` 常包含升高的导音。
5. **声部安排**：内声尽量使用共同音或就近移动，安排低音线和空间；低音区不要同时堆过多 9/11/13。
6. **可解释的情绪**：说明“可能呈现/容易联想到”，不承诺单个和弦一定使人产生某种心情。相同进行随速度和音色能产生反差。
7. **保守输出与审批**：先提交和弦计划，不直接覆写用户原来的 `.jianpu`。生成新文件时征求覆盖许可。
8. **核对限制**：当前 `.jianpu` 是单旋律，但 `.mtrack` 已支持多条 `.jianpu` 轨及 `.drum` 鼓轨叠加混音、导出分轨 MIDI；尚不支持自动生成和弦音符、钢琴卷帘及独立的和弦编辑器。**不能把多轨混音误称为自动和声创作**。

## 在 Codex 中

可以显式 `$melody-harmony` 调用，也可以通过与描述匹配的中文作曲请求自动触发。若要处理具体文件，先用现有 `inspect_score` MCP 工具检查谱面再建议和弦。**Skill 提供知识和工作流，不是模型参数训练**。

## 在 DeepSeek Harness 中

当前不假设 DSH 自动扫描 `.agents/skills`。它通过同一项目 MCP Server 的只读工具 `list_harmony_topics` 和 `read_harmony_guide(topic)` 获取这组知识；可显式要求 Agent 先读取 `workflow` 和 `chords` 再配和弦。所需接口和安装说明见 `docs/HARMONY_SKILL_INTEGRATION.md`。

## 建议输出格式

```text
调性 / BPM / 拍号 / 风格

小节 | 强拍旋律音 | 基础和弦 | 色彩和弦 | 和声功能 | 理由/情绪倾向
1   | E, G       | C        | Cadd9    | I (T)    | 明亮稳定，E/G 是和弦音
2   | D, G       | G        | Gsus4→G  | V (D)    | 保留期待感；检查解决
...

低音线 / 演奏型 / 风险 / 备选 / 可否直接导出多声部：否（当前版本）
```

## 最简调用示例

> 使用 $melody-harmony 检查 `第一乐章/主题.jianpu`，在不改变原旋律的前提下给我两种 8 小节配和弦方案：一种温柔回忆，一种 Game Boy 冒险，并解释每小节和弦的作用。先给计划，不要写入任何文件。
