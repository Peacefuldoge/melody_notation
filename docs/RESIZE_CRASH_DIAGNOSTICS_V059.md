# v0.5.9：窗口拖拽缩放稳定性修复与诊断

## 修复范围

- 将钢琴工具栏从「每次 resize 重建若干行 QHBoxLayout」改成稳定的 Qt height-for-width 流布局，控制项实例不再被频繁移入移出临时布局。
- 钢琴滚动区的可见键数与键宽在事件循环定时器中合并更新（约 16ms 一次）；不再在 `resizeEvent` 中修改滚动区域高度。
- 简谱画布的缩放比例计算仍在 `resizeEvent` 中执行，但高度变化延迟至事件循环处理，降低与 Qt 滚动条几何反馈的嵌套调用风险。
- GUI 模式启动时记录 Python 异常和 `faulthandler` 致命信号堆栈。

## Windows 实机复测

1. 打开简谱，展开底部钢琴；拖动软件边缘连续缩小和放大窗口。
2. 在窗口缩小状态下打开「演奏设置」，调整音色，再拖动窗口尺寸。
3. 连续折叠/展开左侧导航栏，拖动左/右分隔线。
4. 切换简谱、鼓点和多音轨标签并重复 1–3。
5. 在项目根目录执行 `python devtools/resize_stress_gui.py --iterations 250`，自动进行 250 次缩放（测试期间可能出现额外窗口）。

如果仍然闪退，复制以下路径的日志并附上闪退前在做的操作：

`%LOCALAPPDATA%\MelodyNotation\logs\crash.log`

`faulthandler` 并不能保证捕获所有 Qt/C++/驱动层崩溃。有些 Windows 原生异常只有事件查看器的故障模块信息，若没有日志，打开「事件查看器 → Windows 日志 → 应用程序」，查找同时间的 `python.exe` 错误，记下故障模块名称。
